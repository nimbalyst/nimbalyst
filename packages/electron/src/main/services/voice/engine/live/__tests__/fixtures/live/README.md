# Live fixture provenance

These are synthetic recorded-shape fixtures, not recordings from a paid Live session. Event names and wire fields were checked on 2026-09-12 against the [WebSocket guide](https://developers.openai.com/api/docs/guides/voice-websockets?api=live), [delegation guide](https://developers.openai.com/api/docs/guides/live-delegation), [conversation guide](https://developers.openai.com/api/docs/guides/live-conversations), [migration guide](https://developers.openai.com/api/docs/guides/live-migration), and [Live reference](https://developers.openai.com/api/reference/resources/live). IDs, audio samples, commands, timestamps, usage counts, and backend snapshots are illustrative. The `results` wrapper in the late-result fixture is local application input, not a server event. Backend snapshots retain only fields relevant to these reducers.

Reference details: primary output audio has no event ID or timestamps; optional audio timestamps belong to reflected sideband events. A closed session snapshot still says `status: active`. The conversation guide explicitly permits a null error code, although the reference declares a string. `response.event.delegation_id` may be null or omitted. Nested terminal response output is intentionally empty. Transcript text concatenates in delivery order; timestamps group display rows and do not establish turn completion. Distinct event IDs preserve repeated words, even with identical text and intervals.

Concurrency and stale-result handling for an individually superseded delegation are undocumented. The overlapping-delegations fixture is an adversarial scenario, not evidence that the API permits overlap; the reducer must report invalid and emit nothing. It deliberately reuses a call ID across two delegation/response identities to avoid assuming cross-delegation uniqueness. The late-result fixture is exercised sequentially only after the first bound batch has been marked sent. The result-after-close fixture uses the documented session.closed event, which finalizes the whole session and its delegations; it does not invent an individual delegation.closed event. Its result wrapper represents a late application callback that must be dropped locally, not a recorded server response to a submitted stale result.
