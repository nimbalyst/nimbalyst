# Codex shell file tracking

Codex's native tool hooks delimit execution windows; the shared workspace watcher supplies candidate paths. Links are inferred, preserve their file timestamps, and never establish exclusive ownership of a whole-file diff. Structured edits and known editor saves retain their existing handling. A failed MCP call does not disable later shell tracking: definitive app-server completion retires its window even when the post-hook is missing.

## Lifecycle and recovery

The protocol observer accepts only the root thread and current turn, rejects late events from ended turns, and retains yielded commands until a numeric exit code arrives. The attribution service keeps bounded terminal identities so delayed or duplicate hooks cannot reopen a completed tool. Start notifications without pre-hooks guard against false attribution; they cannot establish an earlier write boundary. Unmatched windows are reported before turn/process cleanup. Old generation cleanup cannot close a new generation. A pre-hook whose wait for earlier windows exceeds its budget makes only that command abstain; later commands in the same turn track normally. Another agent session with an active turn in the workspace does not withhold links: they are recorded as shared and noted without a coverage fault. Release waits, bounded, for in-flight completions to persist before the owner disappears.

Tool age alone is not a coverage fault or proof that a command stopped. Watcher loss invalidates cached baselines and marks overlapping tool windows ineligible. Idle providers retain current watcher health without gaining a historical gap. After native recovery, new acknowledged tools can track within the same turn once interrupted windows retire; recovery never reassigns their events. When a healthy pre-command baseline exists, ownership-uncertainty diagnostics wait for content reconciliation: unchanged final bytes need neither an edit link nor an ownership warning. For overlapping sessions whose candidates are all Bash windows, exactly one command naming the changed absolute path selects that window, retaining checkout deferral and observation-health checks. Otherwise actual ambiguous changes remain unattributed even if the competing tool exits before reconciliation; `competingOwners` is informational, while `toolOverlap` remains a coverage fault. Unannounced external writers, detached writes, excluded paths, and uncached deletions remain inference limits.

Command matching shares the pure path-candidate parser extracted from `HooklessAgentFileWatcher`; that watcher's filesystem, symlink, exclusion, and regular-file checks are unchanged. Relative candidates resolve against the window's workspace. The existing parser recognizes absolute paths and relative tokens containing a path separator (such as `./file.ts`); bare filenames, shell expansions, working-directory changes inside a command, and paths beyond the command bound may remain unresolved. Naming a path is an inference tie-break, not process-write evidence or exclusive ownership.

At turn end, acknowledged Bash and patch windows retire silently only when they observed no file events and have neither saved files nor deferred candidates. Event arrival is remembered before asynchronous reads, so queued, excluded, or suppressed candidates cannot masquerade as an event-free window. Shell and patch start notifications without pre-hooks retain conservative unmatched-tool reporting. MCP starts participate in ambiguity but never create a pending-writer marker or report `unmatchedTool`. A Bash window with checkout evidence queues the same reconciliation used by completion, including events awaiting reads: edits persist, unchanged bytes are skipped, and initialization copies are reported as excluded. Missing completion remains an `unmatchedTool` diagnostic when events were observed. Turn end stays synchronous and detaches windows immediately; drain and release wait, bounded, for queued reconciliation and marker cleanup.

## Checkout initialization

Each acknowledged Bash pre-hook captures a bounded Git worktree inventory (1,250 ms total budget, no full workspace content scan). Newly observed worktrees of that same repository defer their candidates until tool completion. The initial worktree HEAD reflog entry pins the checkout revision even if the command edits and commits before filesystem delivery. Batched tree/diff queries distinguish checkout population from authored changes, and final fingerprints reject candidates changed since their observed evidence. Unstable or unavailable initialization evidence produces a coverage gap rather than guessed ownership. Existing worktrees inside the workspace also capture a content baseline: a pinned HEAD for clean tracked files, plus bounded fingerprints of pre-existing dirty and untracked files. Candidates wait for command completion, so an identical delete/rebuild does not become an edit on a cold watcher cache. A reversion of pre-existing dirty content and an edit committed within the command still count. Unrelated nested repositories and non-Git workspaces retain normal inferred tracking.

Markdown still bypasses gitignore for document observation. Attribution applies checkout classification independently, so ignored documentation remains editable without turning copied worktree documents into authored edits. Current clean Git status is never used to erase historical session edits. Worktree creation is covered; arbitrary clones, copies, and branch switches do not acquire this initialization guarantee.

All pre-hook Git queries share the 1,250 ms capture deadline. A query gets half the remaining time for its first attempt and retries a timeout once using the remaining budget; other errors are not retried. Later defer/finish queries get fresh per-query budgets, so the capture deadline does not expire a healthy baseline while the command runs. The overall pre-hook budget is unchanged, within the hook client's 4,500 ms and server's 5 s timeouts. A rejected or timed-out capture makes that command abstain from all inferred links, including candidates under every known worktree root; the next command can capture normally. Defer failures abstain for the affected candidate, and failed reconciliation never falls back to linking its candidates.

## Persistence and coverage

File-link persistence returns explicit persisted, excluded, throttled, quota, or failed outcomes. Transient failure and throttling receive at most three attempts, using the same frozen evidence. A candidate is marked recorded only after persistence succeeds. Exhausted retries produce a coverage gap; they do not invent historical content or transfer the event to another tool.

[ShellTrackingCoverage](../packages/electron/src/main/services/ai/ShellTrackingCoverage.ts) maintains cumulative reason counts and the latest 32 turn summaries. These are event counts, not counts of missing files. Optional bounded diagnostic events retain tool/turn identities; the existing version-1 JSON remains readable without those fields. Legacy age-only diagnostics are retained but do not imply lost edits, and legacy overlap totals are described as ambiguous suppression rather than proven concurrent writers. Current observation health is live-only when loaded after restart. Known editor saves and deliberate exclusions are separate from tracking faults. Health states are unknown, no detected fault, degraded, and unavailable. No detected fault is not a completeness guarantee.

The local `shell_tracking_coverage` table holds one bounded JSON summary per session and cascades on session deletion. The service creates it lazily on either database engine; SQLite migration 43 also creates the destination before a PGLite cutover, and the migrator copies the records. Session metadata and synchronization are untouched. Per-session writes are serialized and coalesced; load failure must not overwrite previously persisted history. A separate optional pending-tool map is saved before acknowledged Bash or patch execution and cleared only after file persistence drains. A conversation turn waiting on an acknowledged MCP call or reasoning alone does not imply an unfinished file write after restart. Uninstrumented tools remain conservative. Hooks that leave the pending-tool map unchanged (every MCP pre/post) cost no durable write; a slow clear is retried in the background and does not disable tracking. Older rows without tool evidence retain their legacy interruption handling; existing warnings are not erased. Earlier gaps survive healthy turns and history compaction.

Database failures stay visible in memory and are retried on later activity or flush. A persistent storage outage cannot guarantee durability; the implementation reports it rather than claiming diagnostics were saved. Commit preparation bounds waiting for accepted file events and terminal cleanup to 1.5 seconds, followed by a separately bounded diagnostics flush. A timeout returns incomplete coverage. Draining cannot recover writes that the watcher never observed.

Hook diagnostics forward `session_id`, `turn_id`, and `agent_type` alongside the event, tool name, and tool-use ID. Bash hooks additionally forward only `tool_input.command` as `command`, joining string argv arrays and truncating to 2,000 characters; no other tool input is forwarded. A real Codex pre-hook probe confirmed the `tool_input.command` string shape. The host caps request bodies at 8,192 bytes and accepts only optional strings up to 2,000 characters for `command`. Commands remain in execution windows and are not added to durable diagnostics or debug logs. The loopback host accepts absent identity fields for older hooks and validates supplied fields as strings of at most 256 characters. Pre- and post-hooks with a foreign turn ID or any present agent type are ignored and counted as informational `foreignTool` events, without degrading coverage. Session ID is diagnostic only: real Codex subagent hooks carry the root session ID. Hooks without a turn ID remain supported unless agent type is present. Pre-hooks recheck turn ownership after asynchronous preparation. Coverage events optionally retain `tool`, `hookSessionId`, `hookTurnId`, `turnMatched`, and `agentType`, including foreign-tool, unmatched-tool, missing-pre, and stale-event diagnostics. `turnId` remains the owning coverage turn; `hookTurnId` is the forwarded identity. `turnMatched` captures equality with the current turn at hook arrival, before draining, and is absent when no turn identity was supplied. Version stays 1, events stay bounded to 32, and older rows and notice text remain compatible. The host's debug hook log includes both turn identities and agent type and is enabled only by `NIMBALYST_SHELL_HOOK_TRACE`.

`checkoutBaseline` events also retain an optional `error` string capped at 200 characters through the same diagnostics path. Messages distinguish the outer `capture timeout` from thrown `capture failed`, `defer failed`, and `finish failed` errors; unresolved candidates identify unavailable or unstable finish evidence. Distinct errors remain distinct events even for the same tool. Older version-1 rows without error text remain readable.

## User surfaces

The file sidebar reads `session-files:coverage` and refreshes on coalesced `session-files:updated` notifications. Scope changes fence stale responses. A current watcher outage displays “File tracking interrupted.” After recovery, remaining historical gaps display “Earlier file tracking gaps.” Sessions without current handle evidence retain the generic “File tracking incomplete” notice. All show their actual reasons; recovery does not erase historical loss. Commit context carries the same summary, including when the recorded file list is empty, and tells the agent to reconcile its actual work against current diffs. Git status supplies candidates, not session ownership. Explicit file selection remains authoritative.

## Verification

The overlap regression starts two real Codex sessions: one acknowledges a long sleep-then-touch command before the other writes `./overlap-writer.ts` with `printf`. It requires nested pre/post hook ordering to prove overlap, a link only to the writer, empty durable pending-tool maps, and `no-detected-fault` coverage for both roots. The isolated macOS run passed on 2026-09-18, including the existing checkout, rebuild, sequential-owner, failed-MCP, question, subagent, and restart controls. Focused tests cover unique, absent, and duplicate command matches through checkout deferral, bounded hook forwarding, and the informational/fault distinction. Unresolved overlap, command truncation, and observation loss during overlap are not exercised by this live case; the path is unverified end-to-end for those variants and on Windows/Linux.

The real-Codex fixture also answers an `AskUserQuestion` turn and requests one native Codex subagent shell write. Its evidence JSON records raw notifications, durable coverage, and hook logs separately for those sessions, plus the pending question before restart. It requires no unmatched-tool fault for the answered question, no root-session link for `subagent.ts`, at least one informational `foreignTool` event, and no detected coverage fault in either turn. Per-hook debug logging is off by default and enabled by `NIMBALYST_SHELL_HOOK_TRACE=1`, which the fixture sets; the running development app is not restarted. Focused tests inject missing completion for turn-end reconciliation and an unmatched MCP start; a successful real run without those missing signals does not verify those paths end-to-end.

The rebuild regression covers cold-cache identical tracked declarations, pre-existing dirty content, real reversions, deletion, and committed writes. Dirty-file snapshots read at most 512 paths and 64 MiB per repository; unsupported or oversized paths abstain individually when touched. The checkout regression creates an isolated Git worktree, commits an authored change in the creating command, and verifies a later edit. The real-Codex fixture additionally populates 7,500 Markdown files through the native watcher, verifies copied files get no links, rejects 300 identically rebuilt declarations, preserves the failed-MCP and sequential-owner controls, and restarts the isolated app while an acknowledged non-writing MCP question is pending. Burst tests verify delivery without count-based restarts and retain deferred native teardown on actual queue overflow.

Focused timeout regressions inject failures at the Git subprocess boundary for both inventory and content capture, check the coverage event's error text, and verify that an identical rebuild gets no link. They also verify retry budgets, a later command's recovery, reconciliation after the capture deadline, late capture rejection, and defer/finish failure abstention. These tests do not establish the cause of the reported failures under load or exercise the running Codex hook/native watcher path; the path is unverified end-to-end.

Focused tests inject missing/late events, failed persistence, throttling, quotas, watcher loss, slow drains, stale turn cleanup, restart, database load failure, and competing UI responses. Real PGLite and SQLite fixtures verify persistence and session-deletion cleanup; a real backend migration verifies coverage survives cutover. The isolated real-Codex Playwright fixture writes before and after an actual failed MCP lookup, verifies sequential session owners and a read-only control, and checks durable coverage and commit context. Run that contract test when the bundled Codex or hook integration changes. Native execution is verified separately per platform.
