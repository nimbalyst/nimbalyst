AI TOOLS
─────────────────────────────────────────────────────────────────────────────

Tool: update_html
├── Use: Complete rewrites, major changes
├── Input: {html, summary}
└── Effect: Replaces entire markup

Tool: replace_text
├── Use: Surgical edits, targeted changes
├── Input: {old_text, new_text, summary}
└── Effect: Finds and replaces text in markup

Context Sent Each Request:
┌──────────────────────────────┐
│ Current HTML markup:         │
│ ```html                      │
│ <div>...</div>               │
│ ```                          │
│                              │
│ Selected element:            │
│ ```html                      │
│ <button>...</button>         │
│ ```                          │
│                              │
│ User message                 │
└──────────────────────────────┘


FILE FORMAT
─────────────────────────────────────────────────────────────────────────────

Plain HTML String (No Parsing!)
│
├── Standard HTML Elements
│   └── <div>, <button>, <input>, etc.
│
├── Tailwind CSS Classes
│   └── "flex gap-4 p-6 bg-background text-foreground"
│
└── Custom Web Components
    └── <wf-icon>, <wf-avatar>, <wf-badge>, <wf-divider>

Example:
┌─────────────────────────────────────────┐
│ markup: `<div class="flex gap-4">      │
│   <div class="w-64 bg-muted">          │
│     <h2>Sidebar</h2>                   │
│   </div>                               │
│   <div class="flex-1">                 │
│     <h1>Main Content</h1>              │
│   </div>                               │
│ </div>`                                │
│                                         │
│ Rendered directly via innerHTML:        │
│ containerRef.current.innerHTML = markup │
└─────────────────────────────────────────┘

KEY DESIGN PRINCIPLES
─────────────────────────────────────────────────────────────────────────────

1. No Parser: Markup is never parsed into AST
   → Simpler, faster, easier for LLMs

2. Direct Rendering: innerHTML for preview
   → Fast, visual feedback, true HTML

3. Tool-Driven: Claude uses tool calls, not text output
   → Predictable, exact changes

4. Offline-First: localStorage persistence
   → Works without backend

5. Minimal Components: Only 4 Web Components
   → Intentional simplicity, encourages standard HTML

6. Semantic Tokens: CSS variables for theming
   → Theme-agnostic designs

7. Snapshot History: Git-like undo/redo
   → Full state capture, clear semantics
